১. Git কী? (আপনার কম্পিউটারের টাইম মেশিন)
ধরুন, আপনি একটি ফাইল বা কোড লিখছেন। আজকে কিছু অংশ লিখলেন এবং সেভ করলেন (Version 1)। কালকে আরও কিছু নতুন জিনিস যোগ করলেন (Version 2)। পরশু দেখা গেল নতুন জিনিস যোগ করতে গিয়ে পুরো ফাইলটা নষ্ট হয়ে গেছে! এখন আপনি যদি আগের দিনের ঠিকঠাক অবস্থায় (Version 1) ফিরে যেতে চান, সাধারণ কম্পিউটারে সেটা করা খুব কঠিন।
Git হলো এমন একটি সফটওয়্যার যা আপনার কম্পিউটারে ইন্সটল থাকে। এটি আপনার ফাইলের প্রতিটি পরিবর্তনের একটি করে "স্ন্যাপশট" বা ছবি তুলে রাখে। ফলে আপনি যেকোনো সময় পেছনের যেকোনো ভার্সনে ফিরে যেতে পারবেন।

২. GitHub কী? (আপনার প্রজেক্টের ক্লাউড স্টোরেজ)
আপনার কম্পিউটার যদি কখনো নষ্ট হয়ে যায় বা হারিয়ে যায়, তবে কম্পিউটারে থাকা Git-এর সব ডাটাও হারিয়ে যাবে। আবার আপনি যদি অন্য কাউকে আপনার ফাইলগুলো দেখাতে বা শেয়ার করতে চান, তবে সেগুলো অনলাইনে রাখা দরকার।
GitHub হলো একটি ওয়েবসাইট (ক্লাউড প্ল্যাটফর্ম), যেখানে আপনি আপনার কম্পিউটারের Git-এ সেভ করা ফাইল ও ভার্সনগুলো অনলাইনে আপলোড করে নিরাপদে জমা রাখতে পারেন।


github.com ওয়েবসাইটে গিয়ে একটি ফ্রি অ্যাকাউন্ট 

ব্রাউজার থেকে git-scm.com/download/win ওয়েবসাইটে যান এবং Click here to download লেখা লিংকে ক্লিক করে সফটওয়্যারটি ডাউনলোড করুন। ২. ডাউনলোড হওয়া .exe ফাইলটিতে ডাবল ক্লিক করে ইন্সটলেশন শুরু করুন। ৩. ইন্সটল করার সময় অনেকগুলো অপশন আসবে—আপনাকে কিছুই পরিবর্তন করতে হবে না। শুধু Next বাটনে ক্লিক করতে থাকুন এবং শেষে Install ও Finish বাটনে ক্লিক করুন।
git --version

git config --global user.name "Your Name"

git config --global user.email "your_email@example.com" 

git config --list 


Repository (সংক্ষেপে Repo) মানে হলো এমন একটি ফোল্ডার, যার ভেতরের সব ফাইলের পরিবর্তন Git নজরদারিতে রাখে। চলুন একটি প্র্যাকটিস প্রজেক্ট তৈরি করি:
কম্পিউটারের Desktop বা Documents-এ my-first-project নামে একটি নতুন সাধারণ ফোল্ডার তৈরি করুন। 
notes.txt নামে একটি সাধারণ টেক্সট ফাইল তৈরি করে তাতে লিখুন: Version 1: Hello Git! এবং ফাইলটি সেভ করুন।

Bash
git init 

ফাইলের বর্তমান অবস্থা দেখা (git status):
Bash
git status 

যাচাই: লাল রঙের লেখায় notes.txt দেখাবে। এর মানে হলো ফাইলটি ফোল্ডারে আছে, কিন্তু Git এখনো এর ভার্সন সেভ করেনি।
২. ফাইলটিকে বক্সে বা Staging Area-তে যোগ করা (git add):
Bash

git add notes.txt

টিপস: ফোল্ডারের সব ফাইল একসাথে যোগ করতে চাইলে git add . লিখতে হয়
যাচাই: আবার git status লিখে Enter চাপলে দেখবেন notes.txt লেখাটি সবুজ (Green) রঙের হয়ে গেছে। অর্থাৎ এটি সেভ হওয়ার জন্য প্রস্তুত।


স্থায়ীভাবে ভার্সন সেভ করা (git commit):
Bash

git commit -m "Version 1: Added initial notes"

এখানে -m মানে হলো Message। ভবিষ্যতে যাতে আপনি বুঝতে পারেন এই ভার্সনে কী কাজ করেছিলেন, তার একটি ছোট নোট এখানে লিখে রাখতে হয়।
যাচাই: স্ক্রিনে 1 file changed, 1 insertion(+) লেখা আসবে। অভিনন্দন! আপনার ফাইলটির Version 1 আপনার কম্পিউটারে নিরাপদে সেভ হয়ে গেছে।

পার্ট ২: GitHub-এ খালি রিপোজিটরি (Repository) তৈরি করা

এবার আমাদের সেভ করা ভার্সনটি অনলাইনে (GitHub-এ) পাঠাতে হবে। তার জন্য GitHub-এ একটি জায়গা তৈরি করতে হবে:

১. ব্রাউজারে github.com ওপেন করে আপনার অ্যাকাউন্টে লগইন করুন।
২. ওপরে ডান কোণায় + চিহ্নে ক্লিক করে New repository সিলেক্ট করুন।
৩. Repository name-এর ঘরে লিখুন: my-first-project
৪. নিচে Public সিলেক্ট করা থাকবে (এটি সবাই দেখতে পাবে; গোপন রাখতে চাইলে Private দিতে পারেন)।
৫. নিচের আর কোনো অপশনে (যেমন Add a README file) টিক দেবেন না—একদম খালি রাখুন।
৬. সবুজ রঙের Create repository বাটনে ক্লিক করুন।

যাচাই: ক্লিক করার পর একটি পেজ আসবে যেখানে Quick setup লেখা এবং একটি লিংক (যেমন: [https://github.com/your-username/my-first-project.git](https://github.com/your-username/my-first-project.git)) দেখতে পাবেন।

যাচাই: ক্লিক করার পর একটি পেজ আসবে যেখানে Quick setup লেখা এবং একটি লিংক (যেমন: [https://github.com/your-username/my-first-project.git](https://github.com/your-username/my-first-project.git)) দেখতে পাবেন।

১. কম্পিউটারকে GitHub-এর ঠিকানা চিনিয়ে দেওয়া:
(নিচের লিংকটির বদলে আপনার GitHub পেজে দেখানো লিংকটি কপি করে বসাবেন)
Bash

git remote add origin https://github.com/your-username/my-first-project.git

২. মূল ব্রাঞ্চের নাম main সেট করা:
Bash

git branch -M main

৩. ফাইলটি GitHub-এ আপলোড করা (git push):
Bash

git push -u origin main



নোট: প্রথমবার push করার সময় আপনার ব্রাউজারে একটি পপ-আপ উইন্ডো আসতে পারে যেখানে Sign in with your browser বাটনে ক্লিক করে GitHub লগইন অনুমোদন (Authorize) করতে হবে।

যাচাই: Git Bash-এ আপলোড সম্পন্ন হওয়ার মেসেজ আসার পর, আপনার ব্রাউজারে গিয়ে GitHub-এর পেজটি Refresh (F5) করুন। দেখবেন আপনার কম্পিউটারের notes.txt ফাইলটি এবং আপনার লেখা কমেন্ট "Version 1: Added initial notes" GitHub-এ চলে এসেছে!


১. উপরের ধাপগুলো অনুসরণ করে notes.txt ফাইলটি GitHub-এ আপলোড করুন।
২. আপলোড হয়ে গেলে, নিজের বোঝার জন্য notes.txt ফাইলে নতুন আরেকটি লাইন লিখুন (Version 2: Second line added), ফাইলটি সেভ করুন এবং শুধু নিচের তিনটি কমান্ড দিয়ে দ্বিতীয় ভার্সনটি আপলোড করে দেখুন:

	git add .

	git commit -m "Version 2: Updated notes"

	git push (দ্বিতীয়বার থেকে শুধু git push লিখলেই চলে!)

কাজটি করতে গিয়ে কোনো এরর বা পাসওয়ার্ড/লগইন সংক্রান্ত সমস্যায় পড়লে  take solution from AI


ভার্সনের ইতিহাস দেখা এবং পুরনো ভার্সনে ফিরে যাওয়া
১. সব ভার্সনের তালিকা দেখা (git log)

আপনি এ পর্যন্ত যতগুলো কমিট (Version) সেভ করেছেন, তার সবগুলোর তালিকা দেখতে my-first-project ফোল্ডারে Git Bash ওপেন করে নিচের কমান্ডটি দিন:
Bash

git log --oneline

যাচাই: স্ক্রিনে নিচের মতো একটি তালিকা আসবে:
Plaintext

a1b2c3d (HEAD -> main, origin/main) Version 2: Updated notes
9f8e7d6 Version 1: Added initial notes


এখানে প্রতিটি ভার্সনের শুরুতে ৭ অক্ষরের একটি ইউনিক কোড (যেমন a1b2c3d, 9f8e7d6) দেখতে পাচ্ছেন—একে Commit ID বা ভার্সন নম্বর বলে।
২. কোন ভার্সনে কী পরিবর্তন হয়েছে তা দেখা (git diff)

notes.txt ফাইলে নতুন একটি লাইন লিখলেন, কিন্তু এখনো git add বা commit করেননি। এখন আপনি দেখতে চান আগের সেভ করা ভার্সনের তুলনায় ফাইলে কী কী যোগ বা বাদ দেওয়া হয়েছে:
Bash

git diff

যাচাই: যে লাইনগুলো নতুন যোগ করেছেন সেগুলো সবুজ রঙের (+ চিহ্নসহ) দেখাবে, আর যেগুলো মুছে ফেলেছেন সেগুলো লাল রঙের (- চিহ্নসহ) দেখাবে।
৩. ভুল পরিবর্তন বাতিল করা (Commit করার আগে)

ধরুন, আপনি notes.txt ফাইলে কিছু লিখতে গিয়ে ভুল করে আগের লেখা মুছে ফেলেছেন এবং ফাইলটি সেভ (Ctrl + S) করে ফেলেছেন। কিন্তু আপনি এখনো git add বা commit করেননি। এখন ফাইলটিকে শেষ সেভ করা ভার্সনের অবস্থায় ফিরিয়ে আনতে লিখুন:
Bash

git checkout -- notes.txt

(অথবা সব ফাইলের পরিবর্তন বাতিল করতে: git restore .)যাচাই: notes.txt ফাইলটি খুলে দেখুন—আপনার ভুল করে লেখা বা মোছা অংশ ঠিক হয়ে আগের ভার্সনের মতো হয়ে গেছে!
৪. পুরনো ভার্সনে স্থায়ীভাবে ফিরে যাওয়া (git revert vs git reset)

যদি আপনি ভুল কিছু commit এবং push করে ফেলেন, তবে আগের ভার্সনে ফেরার দুটি উপায় আছে:

পদ্ধতি ক: নিরাপদ উপায় (git revert) — এটিই সবচেয়ে ভালো
এটি আপনার পুরনো কোনো ইতিহাস মুছে না ফেলে, আগের ভার্সনের লেখাগুলো দিয়ে একটি নতুন ভার্সন (Version 3) তৈরি করে।

১. git log --oneline থেকে যে ভুল ভার্সনটি বাতিল করতে চান তার Commit ID কপি করুন (যেমন a1b2c3d)।
২. কমান্ড দিন:
Bash

git revert a1b2c3d


(নোট: কমান্ড দেওয়ার পর একটি এডিটর স্ক্রিন এলে কীবোর্ডে :wq লিখে Enter চাপুন, অথবা Esc চেপে :q! দিন)।
৩. এরপর git push দিলে GitHub-ও আপডেট হয়ে যাবে।

পদ্ধতি খ: ইতিহাস মুছে ফেলে পেছনে যাওয়া (git reset)
যদি চান Version 2 পুরোপুরি মুছে ফেলে একদম Version 1-এ ফিরে যেতে (যেখানে 9f8e7d6 হলো Version 1-এর ID):
সতর্কতা (Hard Reset)

--hard ব্যবহার করলে ওই ভার্সনের পরের সব কাজ স্থায়ীভাবে মুছে যাবে এবং আর ফেরত আনা যাবে না। তাই নিশ্চিত হয়ে তবেই এটি ব্যবহার করবেন।
Bash

git reset --hard 9f8e7d6

যাচাই: ফাইলটি খুললে দেখবেন Version 2-এর লেখা গায়েব হয়ে গেছে এবং ফাইলটি একদম Version 1-এর অবস্থায় ফিরে এসেছে।

ব্রাঞ্চ (Branch) কী এবং কেন দরকার?
ধরুন, আপনার প্রজেক্টের মূল ফাইলটি (main ব্রাঞ্চ) একদম ঠিকঠাক চলছে। এখন আপনি প্রজেক্টে নতুন একটি ফিচার বা পরিবর্তন যোগ করতে চান। কিন্তু সরাসরি মূল ফাইলে হাত দিলে যদি কোড বা ফাইল নষ্ট হয়ে যায়, তবে পুরো প্রজেক্ট অচল হয়ে যাবে!
তাই আমরা মূল রাস্তা (main) থেকে একটি আলাদা শাখা বা Branch তৈরি করে সেখানে নিশ্চিন্তে পরীক্ষা-নিরীক্ষা করি। পরীক্ষা সফল হলে সেই শাখাটিকে আবার মূল রাস্তার সাথে জুড়ে দিই—একেই Merging (মার্জিং) বলে।

ধাপ ১: বর্তমানে কোন ব্রাঞ্চে আছেন তা দেখা

my-first-project ফোল্ডারে Git Bash ওপেন করে নিচের কমান্ডটি দিন:
Bash

git branch

যাচাই: স্ক্রিনে * main লেখা দেখাবে। তারকা (*) চিহ্নের অর্থ আপনি বর্তমানে main ব্রাঞ্চে আছেন।

ধাপ ২: নতুন ব্রাঞ্চ তৈরি করা এবং সেটিতে যাওয়া
ধরুন, আপনি new-feature নামে একটি নতুন ব্রাঞ্চ তৈরি করবেন এবং সেখানে কাজ করবেন। নিচের কমান্ডটি দিন:

Bash

git checkout -b new-feature

(এখানে -b মানে হলো নতুন ব্রাঞ্চ তৈরি করা এবং সাথে সাথে সেটিতে চলে যাওয়া)।

যাচাই: স্ক্রিনে Switched to a new branch 'new-feature' লেখা আসবে। এখন git branch লিখে Enter চাপলে দেখবেন * চিহ্নটি new-feature-এর পাশে চলে এসেছে!

ধাপ ৩: নতুন ব্রাঞ্চে ফাইল পরিবর্তন এবং ভার্সন সেভ করা

এখন আপনি new-feature ব্রাঞ্চে আছেন। এই ব্রাঞ্চে যা করবেন, তার কোনো প্রভাব main ব্রাঞ্চে পড়বে না।

notes.txt ফাইলটি ওপেন করে নিচে একটি নতুন লাইন লিখুন: Version 3: Working on new feature branch এবং সেভ করুন।

২. এবার Git Bash-এ সাধারণ নিয়মে ফাইলটি সেভ (Commit) করুন:
Bash

git add .

Bash

git commit -m "Added new feature line"

যাচাই: notes.txt ফাইলে আপনার নতুন লেখাটি আছে। এখন মজার জিনিসটি দেখুন—যদি আপনি আবার main ব্রাঞ্চে ফিরে যান (git checkout main লিখে), দেখবেন notes.txt ফাইল থেকে ওই নতুন লাইনটি গায়েব হয়ে গেছে! কারণ ওটি শুধু new-feature ব্রাঞ্চেই সেভ হয়েছে।

নতুন ব্রাঞ্চের কাজ মূল ব্রাঞ্চে যুক্ত করা (git merge)

ধরুন, আপনার নতুন ফিচারের কাজ সফল হয়েছে এবং আপনি এটিকে মূল প্রজেক্টে (main ব্রাঞ্চে) যুক্ত করতে চান।

১. প্রথমে মূল ব্রাঞ্চে ফিরে আসুন:
Bash

git checkout main

(মনে রাখবেন: যে ব্রাঞ্চে যুক্ত করবেন, আগে সেই ব্রাঞ্চে থাকতে হবে)।

২. new-feature ব্রাঞ্চটিকে main-এর সাথে মার্জ করুন:
Bash

git merge new-feature

যাচাই: স্ক্রিনে Fast-forward এবং 1 file changed লেখা আসবে। এখন notes.txt ফাইলটি খুললে দেখবেন main ব্রাঞ্চেও আপনার নতুন লেখাটি চলে এসেছে!

৩. কাজ শেষ হলে অপ্রয়োজনীয় ব্রাঞ্চটি মুছে ফেলা (ঐচ্ছিক):
Bash

git branch -d new-feature

৪. সবশেষে আপডেট হওয়া main ব্রাঞ্চটি GitHub-এ পাঠিয়ে দিন:
Bash

git push


নতুন ব্রাঞ্চটি রিমোটে পুশ করা
প্রথমবার নতুন ব্রাঞ্চ পুশ করার সময় -u (অথবা --set-upstream) ফ্ল্যাগ ব্যবহার করতে হয়, যাতে লোকাল ব্রাঞ্চের সাথে রিমোট ব্রাঞ্চটি লিঙ্ক হয়ে যায়:
Bash
git push -u origin branch-name
(এরপর থেকে এই ব্রাঞ্চে শুধু git push লিখলেই কাজ করবে।)



অ্যাডভান্সড ফিচার ও টিমওয়ার্ক (.gitignore, clone, pull, Fork & PR)

অপ্রয়োজনীয় বা গোপন ফাইল লুকানো (.gitignore)
যেকোনো প্রজেক্টে এমন কিছু ফাইল থাকে যেগুলো আমরা GitHub-এ আপলোড করতে চাই না। যেমন: আপনার পাসওয়ার্ড বা API Key যুক্ত ফাইল (.env), অথবা কম্পিউটারের নিজস্ব টেম্পোরারি ফাইল।
কীভাবে করবেন:
১. আপনার my-first-project ফোল্ডারের ভেতরে ঠিক .gitignore নামে একটি ফাইল তৈরি করুন (খেয়াল রাখবেন, নামের শুরুতে একটি ডট . আছে এবং এর কোনো এক্সটেনশন নেই)।
২. ফাইলটি ওপেন করে যে ফাইল বা ফোল্ডারগুলো বাদ দিতে চান, সেগুলোর নাম লিখে সেভ করুন:
Plaintext

secret.txt
*.log
temp-folder/

যাচাই: এখন ফোল্ডারে secret.txt নামে কোনো ফাইল তৈরি করলেও git status দিলে Git সেটিকে পুরোপুরি এড়িয়ে যাবে এবং কখনোই GitHub-এ আপলোড করবে না!

GitHub থেকে প্রজেক্ট ডাউনলোড (git clone) ও আপডেট আনা (git pull)

আপনি যদি অন্য কোনো কম্পিউটারে বসেন অথবা GitHub-এ থাকা কারও প্রজেক্ট নিজের কম্পিউটারে নামাতে চান, তবে নতুন করে git init করার দরকার নেই।

প্রথমবার প্রজেক্ট নামাতে (git clone):
GitHub রিপোজিটরির সবুজ Code বাটনে ক্লিক করে লিংকটি কপি করুন এবং কম্পিউটারের যেকোনো ফাঁকা জায়গায় Git Bash ওপেন করে লিখুন:

git clone https://github.com/your-username/my-first-project.git

অনলাইনের নতুন পরিবর্তন নিজের কম্পিউটারে আনতে (git pull):
ধরুন, আপনি সরাসরি GitHub ওয়েবসাইটে ঢুকে কোনো ফাইল এডিট করেছেন বা আপনার টিমমেট নতুন কোড আপলোড করেছে।
